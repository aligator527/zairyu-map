# 在留外国人統計 — сборщик данных

Собирает с e-Stat таблицы 在留外国人統計テーブルデータ и сводит каждую в один отсортированный набор данных:

| набор | таблица на e-Stat | периоды | результат |
|---|---|---|---|
| t1 | （国籍・地域別 在留資格別 都道府県別 年齢・性別） | с 2016-12 (до 2023-12 называлась «…テーブルデータ（令和X年末現在）») | `data/zairyu_gaikokujin_pref_age_sex.*` |
| t2 | （国籍・地域別 在留資格別 市区町村別） | с 2023-12 | `data/zairyu_gaikokujin_municipal.*` |

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python estat_crawler.py --all-tables   # скачать xlsx (t1 и t2) в data/raw + каталог всех таблиц в data/catalog.csv
.venv/bin/python build_dataset.py                # t1 -> data/zairyu_gaikokujin_pref_age_sex.{parquet,csv.gz}
.venv/bin/python build_municipal.py              # t2 -> data/zairyu_gaikokujin_municipal.{parquet,csv.gz}
```

Повторный запуск краулера скачивает только новые периоды.

## t1: префектуры × возраст × пол

### Выходные колонки
`period, year, month, region_code, region, nationality_code, nationality, status_code, status,
prefecture_code, prefecture, sex_code, sex, age, age_label, age_group_code, age_group, count`

Сортировка: period → nationality_code → status_code → prefecture_code → age → sex_code.

### Нормализация
- Коды стран приведены к текущей схеме `RR_NNN` (регион_страна); старые названия заменены
  на текущие: スワジランド→エスワティニ, マケドニア→北マケドニア, （朝鮮）→朝鮮, セントクリストファー・ネーヴィス→ネービス.
- `age` = 80 означает «80歳以上»; в 2019-12 возраст был без верхней границы — он обрезан до 80+.
  `age` пусто = 不詳 (только 2016-12 и 2017-12, 3 человека).
- `sex_code` 3 (その他) существует с 2022-12.
- Статусы 在留資格 имеют стабильные коды во всех периодах (特定技能 с 2019-12, 特定技能２号 с 2022-06 и т.д.).

## t2: муниципалитеты (市区町村)

### Выходные колонки
`period, year, month, prefecture_code, prefecture, designated_city_code, designated_city,
municipality_code, municipality, region_code, region, nationality_code, nationality, status_code, status,
sex_code, sex, age, age_label, age_group_code, age_group, count`

Сортировка: period → prefecture_code → municipality_code → nationality_code → status_code → age → sex_code.

### Что отличается между периодами
- **2023-12, 2024-06**: только 市区町村 × 国籍 × 在留資格; колонки пола/возраста пустые (NA).
  Муниципалитеты с ≤10 иностранцами сведены в одну общенациональную строку
  `municipality_code = 99999 «その他»` (`prefecture_code = 99`), поэтому суммы по префектурам
  немного меньше, чем в t1. Общий итог совпадает.
- **2024-12+**: добавлены пол и возраст. Министерство скрывает часть значений («-»), в наборе это
  `秘匿` в текстовых колонках и NA в колонках кодов:
  в муниципалитетах с <5000 иностранцев скрыты пол/возраст, с ≤10 — ещё и страна/статус.
  Итоги по префектурам совпадают с t1 точно.
- 未定・不詳 всегда имеет код `48000` / префектура `48`. В файлах 2024-12+ он был записан как 99999, я привёл его к одному коду.
- В 2023-12 были только названия без кодов: коды стран/статусов/префектур подставлены по другим периодам.
- `designated_city` (政令指定都市) есть в файлах с 2024-12, для более ранних периодов заполнен по коду муниципалитета.
- Названия и коды муниципалитетов оставлены такими, как в каждом периоде (например, реорганизация районов Хамамацу в 2024-01 не сводится).

### Технически
Файлы 2024-12+ хранят данные в модели **Power Pivot**, а не на листе. Они читаются библиотекой
`pbixray` с небольшим патчем: без него pbixray пропускает таблицы, чьё имя начинается на «R»/«H»
(как `R712 テーブルデータ用BD`), и возвращает пустую таблицу.

## Сайт (site/)

Интерактивная карта: префектуры (с 2016-12) и муниципалитеты (с 2023-12), фильтры по
国籍・在留資格・性別・年齢 с перекрёстным просмотром, метрики «人数 / 構成比 / 増減率»,
динамика, таблица-альтернатива карте, EN/日本語, светлая/тёмная тема, мобильная версия.
Полностью статический сайт (Vite + Svelte 5), данные грузятся в браузер (~0.3–0.8 МБ на период).

```bash
.venv/bin/python build_site_data.py     # parquet -> site/public/data (meta.json + *.bin)
cd site && npm install
npm run dev                              # http://localhost:5173
npm run build                            # -> site/dist
```

Границы (`site/public/geo/japan.topo.json`) уже собраны; пересобрать при новой версии N03:
скачать `N03-YYYYMMDD_GML.zip` с 国土数値情報, распаковать в `data/geo/` и запустить
`npm run geo -- ../data/geo/N03-YYYYMMDD.shp`.

Обновление всего после новой публикации на e-Stat: `./update_all.sh`, затем закоммитить `site/public/data`.

### Автообновление
`.github/workflows/update-data.yml` раз в неделю (пн 03:00 JST) запускает `check_updates.py`: он сравнивает
список таблиц на e-Stat (ID и дату 公開（更新）日, включая переиздания) с `sources` в `site/public/data/meta.json`.
Если что-то новое — `update_all.sh` пересобирает данные (скачанные xlsx кэшируются между запусками),
бот коммитит `site/public/data`, после чего Vercel передеплоится сам, а GitHub Pages — через `deploy-pages.yml`.
Вручную: Actions → *Update data from e-Stat* → Run workflow (флаг *force* — пересобрать без изменений).
Учтите: GitHub отключает расписание в репозиториях без активности 60 дней — тогда достаточно нажать Enable.

### Население (показатель «на 1 000 жителей»)
`population.py` берёт 【総計】市区町村別人口 из 総務省「住民基本台帳に基づく人口、人口動態及び世帯数」
(e-Stat toukei 00200241, на 1 января, японцы + иностранцы) → `data/population.parquet`.
Для периода «декабрь N» используется население на 1.1.N+1, для «июнь N» — среднее 1.1.N и 1.1.N+1.

### Иммиграционные бюро (入管局)
Третий уровень карты «入管局»: 8 региональных бюро (地方出入国在留管理局), закрашенных по сумме своих префектур,
плюс слой «入管の管轄» поверх карты префектур и муниципалитетов (границы юрисдикций и офисы).
Юрисдикция и адреса взяты с https://www.moj.go.jp/isa/about/region/index.html и хранятся в
`site/src/lib/bureaus.ts`. 神奈川・兵庫・沖縄 обслуживают 横浜・神戸・那覇支局 (показаны тонкой линией);
у аэропортовых 支局 юрисдикции по месту жительства нет.

### Английские названия
Единый стиль по образцу официальных английских названий органов власти: «Kawasaki City», «Samukawa Town»,
«Ogasawara Village», «Chuo Ward, Sapporo»; тип берётся из японского названия (市/町/村/区), романизация —
из Wikidata без макронов (`data/labels/wikidata_lg_codes.csv`, обновляется `./fetch_labels.sh`).

### Деплой
- **Vercel**: New Project → Root Directory = `site` (настройки в `site/vercel.json`).
- **GitHub Pages**: workflow `.github/workflows/deploy-pages.yml`; в Settings → Pages выбрать Source = GitHub Actions.
  Все пути относительные (`base: './'`), состояние хранится в `#hash`, поэтому сайт работает из любой подпапки.

### Как устроены данные на сайте
- `pref/<period>.bin`, `muni/<period>.bin` — gzip-сжатые колонки (u32 count, u8/u16 коды), см. `build_site_data.py`;
  фильтрация и агрегация — один проход по typed arrays в браузере (`site/src/lib/data.ts`).
- Итоги по Японии/префектуре всегда считаются по полной префектурной таблице; муниципальные
  данные используются только для карты муниципалитетов и выбранного муниципалитета
  (в них Минюст скрывает возраст/пол для мест < 5 000 иностранцев — на карте это штриховка «非公表»).
- Палитра в японских традиционных цветах: 紅 (карминный, от 日の丸 #bc002d) — шкала величин,
  藍 (индиго) — выделение/фокус и «снижение» в шкале 増減率, 墨 — текст, 生成り — фон.
  Шкала: 7 классов с примерно равным числом регионов (квантили), монотонная по яркости (OKLCH);
  в тёмной теме «больше» = светлее. Контраст текста ≥ 5:1 в обеих темах.
